# 26 : PROTOCOLE DE LEÇON PROFONDE

> Ce protocole s'applique aux leçons CORE existantes. Il n'oblige pas à réécrire tous les fichiers : il change la manière de les traverser.

## Mode d'emploi dans la formation complète

Cette méthode est détaillée dans la [route apprenant cohérente](58-ROUTE-APPRENANT-COHERENTE.md). Pour consigner une séance, utilise la [fiche de preuve d'apprentissage](62-FICHE-APPRENTISSAGE-PREUVE.md) ; pour pratiquer le transfert inter-domaines, prends un exercice du [pack systèmes et arbitrages](61-PACK-EXERCICES-SYSTEMES-ET-ARBITRAGES.md).

Les leçons historiques n'ont pas toutes été réécrites à ce format. Lorsque le texte fournit une définition mais pas un exemple travaillé, un exercice autonome, une correction ou un test de transfert, complète ces éléments dans ta fiche. Ce travail comble un manque de pratique sans prétendre que la ressource source contenait déjà ces éléments.

## Avant la leçon : prédiction

Ferme le document et réponds :

- quel problème cette leçon devrait-elle résoudre ?
- quelle mauvaise intuition vas-tu probablement avoir ?
- quelle observation pourrait te faire changer de modèle ?

Une réponse courte suffit. Elle doit être datée avant la lecture.

## Pendant : modèle causal

Ne note pas une définition uniquement. Extrais :

```text
CAUSE → MÉCANISME → EFFET → SIGNAL OBSERVABLE
```

Puis :

```text
INVARIANT
CONDITION DE VALIDITÉ
LIMITE
CONTRE-EXEMPLE
TRADE-OFF
```

## Après : fermeture du document

Sans revoir la leçon :

1. explique le mécanisme avec tes propres mots ;
2. donne un exemple nouveau ;
3. donne un contre-exemple ;
4. donne une situation où la bonne pratique devient mauvaise ;
5. propose une observation qui te ferait changer d'avis.

## Après la pratique

Le livrable doit contenir, lorsque le sujet s'y prête :

- décision ;
- option rejetée ;
- preuve ;
- coût créé ;
- condition de révision ;
- transfert.

## Anti-mémorisation

Une réponse correcte obtenue uniquement par restitution ne ferme pas la compétence. Elle ferme uniquement la couche de vocabulaire.

## Compression intelligente

Si une leçon est longue :

- lire intégralement lors de la première exposition ;
- extraire les invariants et les décisions ;
- revenir ensuite par recherche ciblée ;
- réactiver par rappel et transfert plutôt que relire tout le document.

La richesse documentaire reste disponible ; l'effort cognitif est déplacé de la lecture répétée vers la reconstruction.


## Gate de profondeur : score fondé sur les preuves, pas sur la forme

Pour toute leçon critique et toute nouvelle leçon, évalue les douze fonctions ci-dessous sur une échelle 0–4. Inscris une référence vers la preuve (section, exercice, test, correction ou artefact). Une note 4 n'est recevable que si le critère est observable et vérifiable ; une intention écrite dans le README ne suffit pas.

| Fonction | Preuve attendue pour 4/4 |
|---|---|
| Problème réel | Problème concret et conditions dans lesquelles il compte. |
| Modèle mental | Mécanisme explicable, pas uniquement analogie ou définition. |
| Causalité | Cause → mécanisme → effet → signal observable. |
| Exemple travaillé | Résultat traçable, décisions commentées et hypothèses énoncées. |
| Limites | Contre-exemples, cas limites et erreurs plausibles testés ou résolus. |
| Compromis | Au moins deux options plausibles, avec critères qui changent la décision. |
| Pratique | Production de l'apprenant observable ; ni lecture ni QCM seuls. |
| Autonomie | Une partie significative se résout sans recette ni solution étape par étape. |
| Correction | Critères déterministes, tests, résultat attendu ou revue structurée. |
| Transfert | Variante nouvelle, contrainte inversée ou environnement différent. |
| Rétention | Rappel différé planifié (par exemple J+7/J+30) et critère d'échec/remédiation. |
| Justification | L'apprenant défend la décision, les preuves, les limites et la condition de révision. |

Une ressource dont le rôle est index, grimoire, exemple travaillé ou challenge doit être évaluée selon ce rôle, puis selon la chaîne pédagogique dont elle fait partie. `N/A` est permis uniquement si le rôle est explicite et si la fonction est évaluée ailleurs dans la chaîne ; il ne doit pas être transformé silencieusement en 4/4.

### Règle de publication

- Pour annoncer une maîtrise **4/4**, conserver l'artefact de l'apprenant, le résultat de correction/test, la date, le contexte et idéalement une revue indépendante.
- Aucun critère inférieur à 4/4 ne peut être masqué par une moyenne. Une leçon critique reste `À_REVOIR` si un invariant de sécurité, de correction ou de transfert échoue.
- Les ressources historiques du dépôt ne sont pas réputées satisfaire ce gate par le seul ajout de ce protocole. Leur statut reste `non audité` jusqu'à vérification par ressource ou chaîne de leçons.
- Échantillonner des leçons améliore la confiance du curriculum, mais ne prouve pas que tous les documents ont atteint 4/4. Publier la couverture exacte des ressources évaluées et les limites restantes.

Ce gate est exigeant intentionnellement : il protège la différence entre « la notion existe dans le dépôt » et « l'apprenant peut l'appliquer, la vérifier et la transférer ».
