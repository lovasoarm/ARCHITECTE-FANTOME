# 46 : MARKET EVIDENCE REGISTER : 2026→2035+

## But

Ce registre transforme le marché en **signal vérifiable**, sans transformer une projection en promesse. Il sert à vérifier si ARCHITECTE-FANTOME reste aligné avec les rôles réellement recrutés et avec les compétences qui gagnent ou perdent de la valeur.

**Règle d'or :** un chiffre de marché n'est jamais une preuve de compétence. Une offre d'emploi n'est jamais une preuve que le monde entier demande la même chose. Le registre triangule plusieurs sources et sépare **observé**, **projeté** et **hypothèse**.

## 1. Hiérarchie des preuves marché

| Niveau | Type                                           | Usage                                            |
| ------ | ---------------------------------------------- | ------------------------------------------------ |
| M1     | Source primaire institutionnelle / statistique | projection, emploi, réglementation               |
| M2     | Données agrégées de plateforme ou enquête      | signal de demande/adoption                       |
| M3     | Posting réel récent                            | exigences d'un rôle                              |
| M4     | Témoignage / article / commentaire             | contexte qualitatif uniquement                   |
| M5     | Opinion personnelle                            | jamais suffisant pour une décision de curriculum |

**Une décision CORE importante doit idéalement reposer sur M1+M2 ou M1+M3.**

## 2. Échantillon canonique

À chaque revue, constituer un échantillon d'au moins **30 offres** :

- 10 Staff / Principal / Tech Lead ;
- 5 Senior / Platform / SRE ;
- 5 Solutions / Cloud Architect ;
- 5 AI / AI Engineering ;
- 5 Security / Cloud Security.

Géographies minimales : France, UK ou Allemagne, remote international réellement accessible, et au moins une zone africaine pertinente. Madagascar est ajouté lorsqu'un échantillon crédible existe.

**Ne jamais déduire l'accessibilité juridique ou contractuelle d'un simple mot « remote ».**

## 4. Score AF ↔ marché

Le score d'un posting ne doit pas être un simple pourcentage de mots-clés.

| Dimension                           | Poids |
| ----------------------------------- | ----: |
| Software engineering                |    15 |
| Architecture / system design        |    15 |
| Cloud / platform                    |    10 |
| Reliability / SLO / observability   |    10 |
| Security                            |    10 |
| AI-native engineering / supervision |    10 |
| Data                                |     5 |
| Product / business / cost           |    10 |
| Communication / leadership          |    10 |
| Production / operations             |     5 |

**Pass marché : ≥80/100**, avec trois garde-fous non compensables : architecture, production/operations et communication/leadership ne peuvent pas être tous nuls ou superficiels.

## 5. Familles de compétences à surveiller

### Tendance potentiellement forte

AI engineering, agent orchestration, security for AI/agents, data engineering, platform engineering, reliability, cloud architecture, cost/FinOps, technical leadership, product/technical strategy.

### Tendance de commoditisation possible

Boilerplate code, documentation standardisée, CRUD sans contexte, tests mécaniques, transformation syntaxique, génération de variantes marketing génériques.

Le registre ne doit jamais écrire « métier condamné » à partir d'une seule évolution d'outil. Il doit parler de **tâches**, d'**exposition** et de **valeur résiduelle**.

## 6. Afrique / Madagascar

Ajouter lorsque les données sont suffisamment robustes :

- demande locale ;
- export de services numériques ;
- BPO / IT services ;
- travail distribué ;
- compétences linguistiques ;
- exigences de paiement/contrat ;
- qualité de connectivité ;
- contraintes de fuseau ;
- signaux d'investissement numérique.

**Règle de carrière :** séparer explicitement le marché où la personne vit du marché qu'elle peut servir à distance.

## 7. Journal de décision

Chaque évolution importante doit produire une ligne :


## 8. Cadence

- signal critique : revue immédiate ;
- IA / sécurité / fournisseurs : au moins annuelle ;
- benchmark de postings : tous les 6–12 mois ;
- synthèse 2035+ : scénarios, jamais verdict de certitude.

**Temps CORE ajouté : 0 h.** Ce registre sert à maintenir le curriculum, pas à créer une spécialisation de marché supplémentaire.
