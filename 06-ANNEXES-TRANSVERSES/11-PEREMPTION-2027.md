# LIRE LES INFORMATIONS QUI VIEILLISSENT

Certaines idées du parcours restent solides pendant des années. D’autres dépendent d’un fournisseur, d’une version ou d’un tarif.

## Durable

Les principes de conception, les modèles de données, le raisonnement de debug, les contrats, les tests, la sécurité, l’observabilité et les arbitrages restent les repères principaux.

## À vérifier avant usage

Vérifie toujours la documentation actuelle pour : versions, tarifs cloud, limites de services, interfaces d’outils et comportements spécifiques à un fournisseur.

## Comment lire les exemples datés

Une date indique le contexte de l’exemple. Elle n’en fait pas une règle permanente. Cherche d’abord le principe général, puis vérifie la donnée actuelle avant de prendre une décision de production.

> Une technique peut vieillir. Le réflexe de vérifier ce qui peut vieillir ne vieillit presque pas.
