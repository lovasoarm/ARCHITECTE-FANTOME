> **SCÈNE CRAZYDEVS : Konoha sous siège :** les quartiers, portes et équipes ont des responsabilités différentes. Si tout le monde peut entrer partout, tu n'as pas une architecture : tu as une cour de récréation avec des incendies.

# Code d'honneur CrazyDevs : apprendre doit rester mémorable

Architecte-Fantôme applique un principe CrazyDevs : **la technique doit laisser une empreinte mentale**.

Cela ne signifie pas que chaque paragraphe doit faire une blague. Un contenu Staff sérieux peut
être drôle, étrange, tendu ou simplement raconté comme une scène réelle. Ce qui est interdit est
l'exemple générique sans visage qui pourrait appartenir à n'importe quel cours.

## Le minimum pour un concept important

Chaque concept critique doit posséder au moins un ancrage mémorable parmi :

- une mission ;
- un piège qui casse ;
- un personnage ou une situation reconnaissable ;
- une analogie concrète avec sa limite ;
- un exemple de production qui fait mal ;
- un mini-scénario de décision ;
- un contre-exemple volontairement absurde ou surprenant.

## Le niveau d'intensité

```text
fondations JS/TS → fortement fun, narratif, visuel
construction     → fun + pièges + missions
pilotage         → fun plus adulte : scènes de prod, décisions, pression
Staff            → mémorable par conflit, enjeux, personnages et conséquences
TECH-ILA         → concret et vivant, jamais simple catalogue d'outils
```

Le ton peut devenir plus sérieux sans devenir plat.

## Test avant livraison

Pour toute nouvelle leçon :

> « Si je retire tous les noms d'outils et tous les mots techniques, reste-t-il une scène
> que l'apprenant peut raconter demain à quelqu'un ? »

Si non, ajouter un ancrage avant publication.

## Interdit

- une blague qui remplace l'explication ;
- une référence pop-culture qui déforme le mécanisme ;
- une analogie sans « où elle casse » ;
- dix clins d'œil qui n'ajoutent aucune mémoire ;
- un exemple réaliste mais complètement interchangeable avec n'importe quel cours.

## Règle supplémentaire : CrazyDevs sur tout le parcours

Les univers autorisés ne sont pas réservés aux chapitres JS. Une leçon TECH-ILA, cloud, sécurité, produit, leadership ou psychologie doit elle aussi posséder une scène mémorable quand une explication bénéficie d'un ancrage narratif.

**Test :** enlève les mots « JavaScript », « AWS », « SLO », « DDD » ou « IA ». Si la scène devient un texte interchangeable de formation, il faut la rendre plus incarnée : mission, enjeu, piège, personnage, conséquence.

**Mais :** la scène n'est jamais la solution. La connaissance reste à construire dans les exercices et mini-projets.
