# Cas d’exercice : le portfolio fictif de Noa

Ce cas est un support d’entraînement commun aux exercices 50 à 55. **Noa et ses projets sont fictifs.** Tu n’as pas besoin de construire ton propre portfolio, de posséder un site, d’avoir un client ou de créer un dépôt Git.

## Contexte donné

Noa est développeur junior et veut présenter quelques projets dans un petit portfolio. Le visiteur doit comprendre rapidement ce que fait chaque projet et pouvoir ouvrir une fiche détaillée.

Le portfolio contient pour l’instant ces trois projets fictifs :

| Identifiant      | Nom            | Description courte                        | Technologies                  |
| ---------------- | -------------- | ----------------------------------------- | ----------------------------- |
| `budget-notes`   | Budget Notes   | Suivre des dépenses personnelles fictives | JavaScript, HTML, CSS         |
| `weather-pocket` | Weather Pocket | Afficher une météo de démonstration       | JavaScript, API météo simulée |
| `task-garden`    | Task Garden    | Organiser une petite liste de tâches      | JavaScript, HTML, CSS         |

Une fiche détaillée peut afficher : titre, description, technologies, lien de code, lien de démonstration et projets similaires. Les liens peuvent rester des exemples ou être notés `à définir` ; n’invente pas de dépôts publics.

Les informations de Noa sont : nom d’affichage, rôle, courte présentation, ville facultative et moyen de contact facultatif. N’utilise aucune vraie donnée personnelle.

## Demandes du propriétaire

- « Je veux que les visiteurs trouvent un projet sans parcourir toute la page. »
- « La fiche projet doit être claire et fonctionner sur un petit écran. »
- « Le portfolio doit avoir l’air moderne. »
- « Ajouter un projet ne devrait pas obliger à modifier plusieurs pages à la main. »

Ces phrases sont volontairement incomplètes. Ton travail consiste à les clarifier, pas à inventer une maquette ou une métrique présentée comme déjà validée.

## Faits, hypothèses et limites

- Les trois projets listés sont uniquement des données de démonstration.
- Aucun utilisateur réel n'a encore évalué le portfolio.
- Aucun seuil de performance n'est fourni : tu dois proposer une manière de le mesurer, pas affirmer qu'il est atteint.
- Pour la tâche d'ajout d'un septième projet, tu peux créer un fichier jetable `projects.js` dans `scratch/problem-solving/`. Ne touche pas à un portfolio existant.
- Si tu travailles sur papier, indique `SIMULATION` ; si tu exécutes réellement un fichier local, indique `LAB`.

## Où conserver les réponses

Utilise un dossier local tel que `PREUVES/00-SOCLE/05-PROBLEM-SOLVING/`. Les noms de fichiers proposés dans le challenge sont des repères ; adapte-les si un outil ou un chemin manque. Git et un projet personnel ne sont pas requis.
